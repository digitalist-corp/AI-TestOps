# 개발 계획서 2. 분석 결과 UI (구조 그래프)

2026-10-10 · aQm

## 1. 방향

코드베이스 분석으로 얻은 화면과 전환을 **그래프로 보여 주고, 그 그래프에서 바로 테스트를 만들게 한다.**

- **보는 그림이 아니라 입력 수단이다.** 화면을 순서대로 고르면 그 경로가 테스트 생성 요청이 된다.
- **지금의 목록 화면은 남긴다.** 그래프는 넓은 화면용이고, 좁은 화면과 모바일에서는 목록을 쓴다.
- **새로 저장하는 것은 없다.** 계획서 1에서 저장한 화면 · 요소 · 전환 · 공용 메뉴를 그대로 읽는다.

## 2. 지금 있는 것

계획서 1에서 "구조" 탭이 이미 만들어졌다.

| 있는 것 | 없는 것 |
|---------|---------|
| 화면 목록, 화면을 펼치면 요소와 셀렉터 | 화면 사이의 연결을 한눈에 보는 그림 |
| 요소별 확인 상태(미확인 · 확인됨 · 실패) | 화면 단위로 요약된 상태 |
| 화면 하나를 골라 테스트 만들기 | 여러 화면을 이어 경로로 만들기 |
| 제외 · 메모를 저장하는 API | 제외 · 메모를 넣는 화면 |
| 공용 메뉴 카드 | 어느 테스트가 이 화면을 쓰는지 |

## 3. 화면 구성

"구조" 탭 안에서 **그래프 / 목록**을 전환한다.

| 영역 | 내용 |
|------|------|
| **그래프** | 화면이 상자, 전환이 화살표다. 로그인 화면에서 시작해 왼쪽에서 오른쪽으로 펼친다 |
| **화면 상자** | 경로, 제목, 요소 수, 확인 상태 요약(확인됨 · 실패 개수), 로그인 필요 표시 |
| **상세 패널** | 상자를 누르면 오른쪽에 열린다. 요소와 셀렉터, 메모, 제외, 이 화면을 쓴 테스트 |
| **경로 표시줄** | 고른 화면이 순서대로 나열된다. 요청 문장을 적고 "테스트 만들기"를 누른다 |

정해 둔 규칙.

- **공용 메뉴는 화살표로 그리지 않는다.** 메뉴 링크 7개를 화면 9개마다 그리면 선이 60개가 넘어 읽을 수 없다. 공용 메뉴가 감싸는 화면을 한 묶음으로 표시하고, 묶음 안에서는 어디든 갈 수 있다고 본다.
- **상자의 색은 확인 상태다.** 실패한 요소가 하나라도 있으면 빨강, 모두 확인됐으면 초록, 나머지는 회색. 색만으로 구분하지 않고 개수를 같이 적는다.
- **제외한 화면과 코드에서 사라진 화면은 흐리게** 보여 준다. 숨기지 않는다.
- **이어지지 않는 경로도 만들 수 있다.** 전환이 없는 두 화면을 이으면 경고만 하고 막지 않는다. 분석이 놓친 전환일 수 있다.
- **그래프 라이브러리는 구조 탭을 열 때만 내려받는다.** 다른 화면의 로딩이 느려지면 안 된다.

기술은 React Flow(`@xyflow/react`)와 dagre(자동 배치)를 쓴다.

## 4. 해야 할 일

위에서부터 순서대로 한다. 각 묶음이 끝나면 눈으로 확인할 수 있는 결과가 있다.

### 묶음 1. 그래프가 그려진다

| # | 할 일 |
|---|-------|
| 1 | React Flow와 dagre를 넣고, 구조 탭을 열 때만 불러오게 한다 |
| 2 | 구조 탭에 그래프 / 목록 전환을 만든다. 좁은 화면에서는 목록이 기본이다 |
| 3 | 화면을 상자로, 전환을 화살표로 그리고 자동 배치한다 |
| 4 | 공용 메뉴가 감싸는 화면을 묶음으로 표시한다 |
| 5 | 확대 · 축소 · 화면에 맞추기를 넣는다 |

확인: AI-TestOps 자신의 화면 9개가 겹치지 않고 그려진다. 다른 탭의 첫 로딩 크기는 그대로다.

### 묶음 2. 상자에서 상태가 보인다

| # | 할 일 |
|---|-------|
| 6 | 조회 API에 화면별 확인 상태 개수(확인됨 · 실패 · 미확인)를 더한다 |
| 7 | 화면 상자를 만든다. 경로, 제목, 요소 수, 상태 색, 로그인 필요, 제외 · 사라짐 표시 |
| 8 | 상세 패널을 만든다. 지금 목록에서 펼쳐 보이는 요소 표를 옮겨 쓴다 |
| 9 | 상세 패널에서 메모를 적고 제외를 켜고 끈다 |

확인: 실패한 요소가 있는 화면이 빨갛게 보인다. 메모와 제외가 다시 분석한 뒤에도 남는다.

### 묶음 3. 경로를 골라 테스트를 만든다

| # | 할 일 |
|---|-------|
| 10 | 화면을 순서대로 고르면 경로 표시줄에 쌓인다. 빼기와 순서 바꾸기가 된다 |
| 11 | 고른 경로를 그래프에 강조하고, 이어지지 않는 구간은 점선과 경고로 보여 준다 |
| 12 | 경로와 요청 문장으로 테스트 생성을 요청한다. 화면 순서가 AI에 전달되게 한다 |
| 13 | 만들어진 작업으로 가는 링크를 보여 준다. 승인 절차는 지금과 같다 |

확인: 로그인 → 프로젝트 목록 → 프로젝트 상세를 골라 만든 테스트가 그 순서대로 움직인다.

### 묶음 4. 실행 결과가 돌아온다

| # | 할 일 |
|---|-------|
| 14 | 상세 패널에 이 화면을 쓴 테스트와 최근 실행 결과를 보여 준다 |
| 15 | 분석이 도는 동안 읽은 화면부터 그래프에 나타나게 한다 |
| 16 | 화면이 많을 때를 위한 검색과 상태 필터를 넣는다 |
| 17 | 자체 회귀 테스트에 구조 탭 진입과 경로 선택을 추가한다 |

확인: 테스트를 실행하고 구조 탭으로 돌아오면 상자의 색과 개수가 바뀌어 있다.

## 5. 다 됐다고 보는 기준

- 분석 결과가 그래프로 그려지고, 목록과 같은 내용을 보여 준다.
- 화면 여러 개를 골라 테스트를 만들 수 있다.
- 최근 실행 결과가 그래프에 반영된다 (PRD F-10).
- 화면 60개(분석 상한)에서도 원하는 화면을 찾을 수 있다.
- 구조 탭을 열지 않으면 그래프 라이브러리를 내려받지 않는다.

## 6. 먼저 정할 것

| 정할 것 | 제안 |
|---------|------|
| 배치를 사용자가 바꾸면 저장하나 | 저장하지 않는다. 열 때마다 자동 배치한다. 화면이 늘면 저장한 배치가 어긋난다 |
| 화면 미리보기 그림을 넣나 | 넣지 않는다. 코드만 읽어서는 그림이 없다. 사이트 탐색을 붙일 때 넣는다 |
| AI가 제안하는 테스트 후보 | 이번에는 넣지 않는다. 경로를 사람이 고르는 것부터 만든다 |
| 그래프에서 화면이나 전환을 손으로 추가하나 | 하지 않는다. 편집은 제외와 메모까지만 한다 |

## 7. 나중에 할 것

- **AI가 제안하는 테스트 후보.** 그래프에서 자주 지나는 경로를 AI가 골라 제안한다. LangGraph(계획서 3)와 함께 다룬다.
- **화면 미리보기 그림.** 사이트 탐색이 붙으면 실제 화면을 찍어 상자에 넣는다.
- **공용 메뉴 요소의 확인 상태.** 지금은 화면의 요소만 실행 결과로 갱신된다.
- 경로 접두사로 화면 묶기(`/projects/...`를 한 덩어리로).
