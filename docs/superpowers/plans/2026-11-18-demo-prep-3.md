# 3차 시연 준비 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 11/24 시연 전에 팀원 권한 화면 · 실행 범위 · 동시 실행 · 로그인 IP 판단을 바로잡고, 시연 순서를 배포 서버에서 리허설 가능한 문서 · 도구로 만든다.

**Architecture:** 웹은 권한을 `useAccess().canManage(projectId)` 한 가지로 가리고, 탭 가드는 `ProjectDetailPage` 한 곳. 실행 범위 · 동시 실행은 서버 `ExecutionQueryService.triggerRun`과 `PlaywrightGrep`(#135)에 모은다. 리허설은 배포 서버의 self-hosted 러너에서 러너 이미지로 Playwright를 돌리는 수동 워크플로.

**Tech Stack:** Spring Boot 3.3 / Java 21, React 19 + Vite + vitest, Playwright 1.53, GitHub Actions (self-hosted `playops-testserver`)

**Spec:** `docs/superpowers/specs/2026-11-18-demo-prep-3-design.md`

## Global Constraints
- 마이그레이션은 V21부터 (이번 계획은 필요 없음)
- 이슈 하나 = 브랜치 하나 = PR 하나, 쌓은 PR은 맨 위만 dev로 머지, 나머지는 "함께 반영" 댓글로 닫음
- 스크린샷은 `docs/screenshots/<브랜치에서 접두어 뺀 이름>/`에 커밋, PR에는 `?raw=true` 링크
- 커밋 메시지 한국어 + `feat:`/`fix:`/`docs:`, 끝에 Co-Authored-By
- 비밀번호 · 토큰 · Authorization · Cookie를 로그 · 문서 · 커밋 · PR · 채팅에 남기지 않는다
- 화면 문구에 코드 용어 금지, 한국어
- 새 grep 함수 금지 — `PlaywrightGrep.testTitle/describeTitle/anyOf` 재사용
- API 테스트는 Docker JDK로 임시 복사본에서, 웹은 `docker exec playops-web npx vitest run`

## Review Focus
- 팀원이 관리 전용 탭 주소를 직접 열 때 → 기본 탭으로 돌려보낸다 (Task 1 테스트)
- 같은 프로젝트에 실행 요청 두 개가 동시에 들어올 때 → 하나만 생기고 하나는 409 (Task 3 동시성 테스트)
- 다른 프로젝트가 실행 중일 때 → 막지 않는다 (Task 3), 배포 게이트(playops-self)와 시연 단계(example.com)는 서로 다른 프로젝트
- 채팅 도구 이름이 여러 케이스에 맞을 때 → 실행하지 않고 후보를 돌려준다 (Task 2)
- 시연 PM 비밀번호가 `.env`에서 바뀌었을 때 → 다음 기동에 새 값으로 로그인된다 (Task 5)
