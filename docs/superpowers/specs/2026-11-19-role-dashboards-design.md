# AI-TestOps 역할별 대시보드 · 엑셀형 표 통합 설계 (2026-11-19)

> 아래 다섯 과제의 Arena 결과를 하나로 합쳤다: 메뉴 구조(nav), 관리자 홈(admin), PM 홈(pm), 팀원 홈(member), 공통 엑셀형 표(grid).
> - pm과 member는 심판 판정과 최종안이 모두 없었다. 이 문서에서 인수인계 3-1과 조사 문서 2절을 근거로 새로 설계했다.
> - 기준 코드는 dev 브랜치(d340523)다. 마이그레이션은 최신이 `V21__user_password_change_required.sql`이고, V22 이후 번호는 어느 브랜치에도 아직 없다(확인함).

## 1. 한 줄 요약과 원칙 3개

**한 줄 요약:** 업계 표준 틀을 그대로 따른다. 틀은 테스트 케이스, 테스트 런, 판정 6값, 결함, 보고서, 역할별 홈이다. AI 생성, 실제 브라우저 증거, 자가 치유, 원인 분류, 승인 게이트, 학습 루프는 따로 메뉴를 두지 않고 그 틀 안의 **칸 · 꼬리표 · 버튼**으로 넣는다. 탭 id와 URL은 하나도 바꾸지 않는다.

**원칙**

1. **판정은 닫고, AI에는 칸을 연다.**
   - 판정은 표준 6값(미수행 · 통과 · 실패 · 차단 · 재시험 · 해당 없음)만 쓴다.
   - AI가 내놓는 것은 원인 · 출처 · 작성 상태 · 조치 · 치유 칸에만 들어간다.
   - 새 AI 기능이 생기면 판정 enum이나 메뉴는 그대로 두고 칸을 하나 더한다.
2. **사실은 자동으로, 추정은 사람이 확정한다.**
   - 자동 판정은 실행 결과라는 사실(PASSED/FAILED/SKIPPED/ERROR)에서만 나온다.
   - 원인, 차단 제안, 심각도, 케이스 승인, 코드 반영은 사람이 확정한다. 코드 반영은 `AiJobService.applyDiff` 한 곳에서만 일어난다.
   - 통과율 · 보고서 집계에는 확정된 값만 쓴다.
3. **홈은 보고 이동만 한다. 쓰기는 각 탭에서 한다.**
   - 홈에서 할 수 있는 것은 숫자 보기, 필터를 건 채 이동, 실행 · 다시 실행뿐이다.
   - 승인, 판정 덮어쓰기, PM 지정, 종료는 각 탭의 서랍과 관리 화면에서 한다.
   - 시연 리허설이 보는 글자와 탭 id는 유지한다.

## 2. 용어 · 판정 값 · 계산식 (모든 화면 공통)

### 2-1. 용어

| 낱말 | 뜻 | 쓰지 않는 말 |
|---|---|---|
| 테스트 케이스(케이스), C번호 | 저장소의 항목 하나(spec 경로 + 케이스 제목) | 시나리오, 계획 항목 |
| 테스트 런(런), R번호 | 이번에 수행할 케이스 묶음(V24 이후). 그전에는 '계획 표'가 이 역할을 한다 | 차수(런 안의 회차는 '실행 #n') |
| 테스트, T번호 | 런 안의 케이스 한 줄 | — |
| 실행 | 러너가 브라우저로 돌린 것(실행 #n) | — |
| 수행 · 수행자 | 판정을 남긴 것과 그 주체(자동 #n / 사람 이름) | — |
| 결함, D번호 | 실패에서 생기는 추적 단위 | '실패'와 같은 뜻으로 쓰지 않는다 |
| 섹션 | 대분류 · 중분류 트리 | 폴더 |
| 스위트 | 실행할 때 고르는 묶음 필터 | 섹션과 같은 뜻으로 쓰지 않는다 |
| 진척률 / 통과율 | 2-4의 식 | 진척도, 합격률, 성공률 |
| 승인 대기 | 2-4의 식 | 검토 대기(이 말은 케이스 작성 상태에만 쓴다) |

### 2-2. 판정 값 (6개로 닫음)

| 코드 | 화면 | 엑셀 내보내기 | 가져오기에서 받는 값 | 색 | 자동으로 매기는 경우 |
|---|---|---|---|---|---|
| UNTESTED | 미수행 | Untested | 미수행, Untested, Not Run, 빈칸 | 회색 | 결과가 없음 |
| PASSED | 통과 | Pass | 통과, Pass, 성공 | 초록 | 케이스 결과 PASSED |
| FAILED | 실패 | Fail | 실패, Fail | 빨강 | 케이스 결과 FAILED |
| BLOCKED | 차단 | Block | 차단, Block, Blocked | 주황 | 실행 자체가 ERROR라 케이스 결과가 없음 |
| RETEST | 재시험 | Retest | 재시험, Retest | 보라 | 자가 치유나 수정안이 반영됐는데 그 뒤 실행이 없음 |
| NA | 해당 없음 | N/A | 해당 없음, N/A, NA, Skipped | 연회색 | 케이스 결과 SKIPPED |

- **CANCELLED(실행 중지)는 판정을 바꾸지 않는다.** 이전 판정을 유지하고, 이전 판정이 없으면 미수행이다. 시연 4단계에서 "실행 중지"를 눌러도 5건이 차단으로 바뀌지 않는다.
- 필터 목록과 헤더 툴팁에는 `통과 (Pass)`처럼 영문을 함께 적는다. 표 안의 칸에는 한글만 쓴다.
- 실행 상태(예약됨 · 대기 · 실행 중 · 중단 중 · 중단됨 · 완료 · 오류)는 판정과 다른 칸에 둔다. 지금은 `lib/utils.ts`의 `executionStatusLabel`에 `PASSED: '성공'`이 섞여 있는데, 이것을 실행 상태 칸과 결과 칸으로 나눈다.
- 차단 · 재시험 · 해당 없음은 판정 이력 테이블(V24)이 생긴 뒤에 나타난다. 그전에는 미수행 · 통과 · 실패 3값만 보인다(`PlanItem.lastStatus`).

### 2-3. 그 밖의 값

| 항목 | 값 | 비고 |
|---|---|---|
| 판정 출처 꼬리표 | `자동`(실행 사실) / `수동 · 이름`(사람) | 빗금 같은 시각 기호는 쓰지 않는다 |
| AI 꼬리표 | `AI`(추정, 회색) → 사람이 고르면 `확정` | ✦ 기호는 쓰지 않는다 |

| 원인 규칙(1차, 지금 데이터) | coverage `issues[].kind`를 specPath로 맞춘다. SELECTOR_FAILED → 스크립트 오류, OPEN_FAILED · LOGIN_REQUIRED → 환경, NOT_REACHED · EXPLORE_STOPPED → 쓰지 않음(미분류). 재시도(`attempt_index > 0`)에서 통과하면 → 불안정 | 근거 없이 '제품 결함'으로 몰지 않는다. 남는 것은 **미분류** |

| 결함 상태 | 시연 전: 미해결 / 해결. V25 뒤: 신규 · 진행 중 · 해결 · 종결 · 재발 | 필터 묶음 이름 '미해결'(신규 + 진행 중 + 재발)과 '해결'은 그대로 둔다 |
| 케이스 작성 상태 | 초안 · 검토 대기 · 승인 · 폐기 | AI 생성 케이스는 '검토 대기'로 들어온다 |
| 케이스 출처 | 코드 · 녹화 · AI · 가져오기 · 직접 | 지금은 spec 단위 `scenario_origin.source`, coverage `flows[].source`를 쓴다 |
| 프로젝트 상태 | 계획 · **진행 중** · 종료 | 지금 라벨 '실행'은 실행(러너)과 겹친다. 바꾸는 것은 시연 뒤 |
