# A트랙 설계 — 계획 기반 테스트 관리 (이슈 #75~#79)

작성 2026-11-17 · 담당 장준호 · 기한 2026-11-24 · 근거: 11/13 개선계획서

## 왜

지금 화면은 "코드가 있고 → 돌린다"는 개발자 흐름이라 QA·현업이 **무엇을 테스트할 계획이고, 얼마나 끝났는지**를 볼 곳이 없다.
케이스 하나를 계획 항목 하나로 보고, 계획 표를 기준으로 완료율과 오류 화면을 첫 화면에 보여 준다.

## 목표 / 비목표 / 실패 조건

- 목표: 메뉴 5단계(입력 → 계획 → 실행 → 대시보드 → 설정), 엑셀형 계획 표, 계획 기준 품질 지표 첫 화면.
- 비목표: 기능(feature) 매핑(F-3), 테스트 제목이 바뀐 케이스 자동 연결, 계획 순서대로 실행 강제. 모두 1단계 백로그(#89).
- 실패 조건: 기존 화면으로 가는 길이 끊김 · 윤재(B트랙) 작업과 같은 파일에서 큰 충돌 · 지표 숫자가 계획 표와 안 맞음.

## 제약

- DB 변경은 V11 하나 (B는 V12).
- 메뉴 정의(`shellNav.ts`, `projectWorkspace.ts`)는 A가 소유. #75를 가장 먼저 머지해 B가 그 위에서 작업하게 한다.
- 결함 수는 B의 F-4(#80)가 만든다. A는 결함 칸을 만들지 않고, B가 #81에서 계획 표에 칸을 붙인다. *(내 판단)*

## 접근 방식 (결정: 1번)

1. **기존 사용/미사용 표(`scenario_case_settings`)에 계획 칸 추가** — 선택. 케이스 식별·저장 코드와 "미사용은 실행 제외"가 이미 같은 행에 있다.
2. 계획 항목 전용 새 표 — 구조는 깔끔하지만 사용 여부와 계획이 두 표로 갈라져 동기화 코드가 생긴다. 1주 일정에 부담.

## 설계

### 데이터 (A-2, #76)

V11: `scenario_case_settings`에 `sort_order INT NULL`, `assignee VARCHAR(100) NULL`, `due_date DATE NULL`, `priority VARCHAR(10) NULL` 추가.

- 계획 항목 = `node_type='TEST'` 행. 식별 키는 기존 그대로 (프로젝트, spec 경로, grep). grep은 테스트 제목에서 만든 값이라 사실상 "파일 경로 + 테스트 제목".
- **제목이 바뀌면 다른 항목이 된다**(옛 행은 고아로 남음). 사용 여부도 지금 똑같이 동작하므로 이번엔 문서화만 한다.
- 행이 아직 없는 케이스는 "사용 · 계획 칸 비어 있음"으로 본다 (지금의 사용 여부 기본값과 같음).
- 우선순위 값: `HIGH` / `MEDIUM` / `LOW` / null. 담당자는 자유 입력 문자열 *(내 판단: 사용자 목록 연동은 1단계)*.

### API (A-2)

- `GET /api/projects/{id}/plan` → `{ items: PlanItem[], summary: PlanSummary }`
  - `PlanItem`: specPath, grep, title(마지막 테스트 이름), describePath, enabled, sortOrder, assignee, dueDate, priority, lastStatus(`PASSED|FAILED|SKIPPED|null`), lastRunAt.
  - 목록은 시나리오 분석 결과(`PlaywrightScenarioService.analyze`)의 TEST 노드를 펼친 것. 정렬: sortOrder(null은 뒤) → 파일 경로 → 파일 안 줄 번호.
  - 최근 결과: 그 프로젝트 실행들의 `execution_case_results` 중 같은 spec 경로 + 마지막 제목이 같은 가장 최근 행 (웹 `casesByScreen`과 같은 매칭 규칙).
  - `summary`: total, enabled, disabled, passed, failed, notRun, completionRate. **완료율 = 최근 성공 ÷ 사용 중 항목**, 미사용은 분모에서 빼고 건수만 따로. 사용 중 항목이 0이면 0.
- `PATCH /api/projects/{id}/plan/items` body `{ specPath, grep, enabled?, assignee?, dueDate?, priority? }` — 보낸 칸만 바꾼다. 없으면 행을 만든다.
- `PUT /api/projects/{id}/plan/order` body `{ items: [{specPath, grep}] }` — 받은 순서대로 sortOrder 0..n-1.
- `PATCH /api/projects/{id}/plan/items/enabled` body `{ items: [{specPath, grep}], enabled }` — 일괄 사용/미사용.
- 실행은 바꾸지 않는다. 미사용 케이스는 이미 `--grep-invert`로 빠진다.

### 메뉴 (A-1, #75)

- 상단 그룹 순서: **입력**(저장소 연결·코드/사이트 분석) → **계획**(계획 표, 테스트 편집, 클릭으로 만들기, 구조=맵 보기) → **실행**(실행 이력, 결과, 예약 실행) → **대시보드** → **설정**(환경 정보·코드 편집기). AI 그룹은 지금처럼 켜졌을 때만.
- 프로젝트 기본 탭은 대시보드 그대로.
- 구조 탭의 분석 버튼(저장소 연결 · 코드로 찾기 · 사이트 주소로 찾기)을 입력 단계 화면으로 옮긴다. 구조 탭은 그래프 보기만 남고 계획 그룹 안 '맵 보기'로 들어간다.
- 탭 id는 바꾸지 않는다 (주소·북마크·B 작업 보호). 새 탭 id는 `input`(입력: 분석 패널)과 `plan`(계획 표) 둘. *(구현 계획 때 조정: 분석 상태 코드가 구조 탭에 묶여 있어 같은 컴포넌트를 `mode` 하나로 나눠 쓴다.)*

### 계획 표 화면 (A-3, #77)

- 새 탭 `plan`. 이미 쓰는 ag-grid-community로 만든다.
- 열: 사용 체크 · 순서(끌어 옮기기) · 계획 항목(테스트 제목, describe 경로는 흐리게) · 화면 · 담당자 · 마감일 · 우선순위 · 최근 결과.
- 화면 열은 웹의 기존 화면 매핑(`casesByScreen`)을 재사용, 없으면 "미지정".
- spec·grep 같은 코드 용어는 보이지 않게. 파일 이름은 툴팁으로만.
- 셀을 고치면 바로 PATCH, 실패하면 값 되돌리고 알림. 맨 위에 "체크한 N건 실행" 버튼 → 기존 전체 실행 호출.

### 품질 현황 첫 화면 (A-4, #78)

- 대시보드 맨 위 요약을 `plan.summary` 기준 지표로 교체: 전체 계획 · 사용/미사용 · 성공 · 실패 · 미수행 · 완료율 (미해결 결함은 B의 #80이 머지되면 추가).
- 그 아래 "오류가 난 화면" 목록 (화면별 실패 건수, 많은 순). 기존 차수 비교·화면별 케이스 트리는 그 아래에 그대로 둔다.
- 계획 표를 바꾸고 대시보드로 오면 다시 읽으므로 바로 반영된다.

### 여유 (A-5, #79)

11/20 점검에서 결정. 스위트 필터, 구조 지도 노드에 저장된 스크린샷 표시.
