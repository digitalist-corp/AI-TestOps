# 3차 시연 준비 설계 (2026-11-18)

11/24 3분 시연을 막힘 없이 돌리기 위한 마무리. 사용자(PM · FE 장준호)와 합의한 내용과 빌더 판단을 구분해 적는다.

## 의도
- 시연에서 "팀원은 보기 · 실행, PM은 수정"이 화면에서도 그대로 보여야 한다 (서버가 막는 버튼을 팀원에게 보이지 않기)
- 고른 케이스만 정확히 돈다 (비슷한 제목이 딸려 돌지 않기)
- 같은 프로젝트를 동시에 두 번 돌리지 않는다 (서버가 막고, 화면은 안내)
- 가입 · 로그인 횟수 제한이 실제 접속 IP 기준으로 동작한다
- 시연 순서를 문서로 고정하고 배포 서버에서 실제로 돌려 확인, 리허설 뒤 명령 하나로 되돌린다

## 비목표 · 안티 목표
- 시연 중 계정 전환 (합의: 하지 않음)
- 새 grep 함수 (합의: #135 `PlaywrightGrep` 재사용)
- 비밀번호 · 토큰을 문서 · 커밋 · 로그 · 채팅에 남기는 것 (임시 로그에도 Authorization · Cookie 금지)
- 예약 실행 · AI 사후 검증 실행까지 막는 것 (빌더 판단: 사람이 누르는 실행 경로만 같은 지점에서 막는다)

## 접근 (합의)
1. **권한 화면 정리**: 팀원에게 보이지만 서버가 403으로 막는 버튼을 프로젝트 화면 전체에서 찾아 숨기고, 서버 403을 테스트로 남긴다. 화면 지도 "화면 직접 추가하기"부터.
2. **정확 일치 통일**: 테스트 탭은 케이스 키(파일 · grep · 종류)를 서버에 넘기고 서버가 `PlaywrightGrep`으로 패턴을 만든다. 채팅 실행 도구는 파일 + 이름이 실제 케이스와 정확히 맞으면 정확 일치로 실행, 아니면 그 파일의 케이스 이름 후보를 돌려줘 다시 고르게 한다. 스위트 grep(사용자가 쓴 정규식)은 그대로.
3. **동시 실행 409**: `ExecutionQueryService.triggerRun`(전체 · 선택 · 스위트 · 결함 다시 실행 · 채팅이 모두 지나는 곳)에서 같은 프로젝트의 PENDING · RUNNING · CANCEL_REQUESTED 실행이 있으면 409 "이미 실행 중입니다". 동시 요청은 프로젝트별 잠금으로 직렬화 (빌더 판단, 서버 한 대 기준). 화면은 서버 메시지를 그대로 안내.
4. **#121**: 두 번 배포. 1차에 임시 로그(X-Forwarded-For · X-Real-IP · 원격 주소만)와, 배포 Actions가 터널 주소로 요청 하나를 보내 그 로그를 출력하는 단계를 넣는다. 확인 뒤 2차에 "원격 주소가 사설 · 루프백(같은 도커 네트워크의 프록시)일 때만 X-Forwarded-For를 믿고, 오른쪽에서부터 첫 비신뢰 주소를 쓴다"로 고치고 임시 로그 · 확인 단계를 지운다. IP 판단은 `AuthInterceptor` · `AuthController` 두 곳의 중복을 한 곳으로.
5. **시연 (#88)**: 시연용 PM 계정으로 처음부터 진행, 게스트는 로그인 화면 버튼만. 해결 장면은 (가) — 코드 편집기에서 시연 spec의 링크 이름을 고치고 다시 실행.
   - 시연용 PM 계정: 시드(시연 프로젝트 PM). 아이디 · 비밀번호는 `.env`(`DEMO_PM_USERNAME` · `DEMO_PM_PASSWORD`)로만. 비밀번호가 비면 계정을 만들지 않는다. 서버 `.env`에 없으면 배포가 무작위 비밀번호를 서버 `.env`에만 추가한다 (빌더 판단 — 서버 접속자만 값을 안다)
   - 되돌리기 명령: `scripts/demo-reset.sh` — `.env`의 PM 계정으로 로그인 → 시연 spec을 저장소 원본으로 덮어씀(기존 파일 저장 API) → 시연 프로젝트 한 번 실행 → 미해결 결함 1건 확인
   - 리허설: 수동 실행 워크플로 `demo-rehearsal.yml` — 서버에서 러너 이미지로 시연 순서를 Playwright로 돌리며 단계별 스크린샷을 아티팩트로 남기고, 끝에 되돌리기 명령을 실행
   - 문서 `docs/demo/시연-순서.md`: 단계마다 클릭 위치 · 말할 한 줄 · 실패 시 대처, 코드 편집기에서 고칠 파일 · 줄, 되돌리기 명령
6. **시연 뒤 이슈**: (a) 결함 다시 실행 패턴 500자 초과 시 범위가 넓어짐 (b) 영상 · 스크린샷 주소에 로그인 토큰 (c) HTML 리포트 · trace에 입력값 원문 — 각각 이슈로 만들고 #89에 연결.
