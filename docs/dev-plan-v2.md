## 1. 진행 방식

도장깨기. 한 주에 주제 하나를 잡고 네 명이 모두 붙어 끝낸 뒤 다음으로 넘어간다. 업무명 앞에 "(여유)"가 붙은 것은 그 주에 못 끝내면 8주차로 넘긴다.

| 요일 | 하는 일 |
|---|---|
| 월 | 주제 시작. 업무와 선행 관계 확인, 계약 문서 다시 읽기 |
| 수 | 중간 점검. 선행 업무가 끝났는지 확인하고 막힌 사람을 돕는다 |
| 금 | 기능 마감. 이후로는 새 코드를 쓰지 않고 붙이기만 한다 |
| 토 ~ 일 | 통합 확인과 PR 병합. 완료 기준을 채웠는지 보고 그 주를 닫는다 |

## 5. 공통 규칙

- 작업 브랜치는 dev에서 따고 dev로 PR을 올린다. main으로는 dev만 올릴 수 있다 (pr-guard).
- 커밋 메시지는 한국어로 쓰고 feat: fix: 같은 종류를 앞에 붙인다.
- AI가 만든 코드는 담당자가 읽고 실행해 본 뒤 PR을 올린다. 설명하지 못하는 코드는 올리지 않는다.
- 바뀌지 않는 원칙 세 가지 — LLM 호출은 LlmGatewayService 단일 출구로만, 컨테이너는 API 키를 보지 않음, 파일을 바꾸는 작업은 사람 승인 후 반영.
- 한 주를 닫을 때 자체 회귀 테스트를 돌리고, 새 화면이 생겼으면 회귀 케이스를 추가한다.
- 모든 PR은 다른 팀원 한 명 이상이 검토한 뒤 병합한다.
