### 3-1. #80 결함 리스트 — 서버

- 결함 = 케이스(spec 경로 + 제목)의 **최근 실행이 실패**면 미해결, 이후 실행에서 통과하면 해결. 별도 결함 테이블 없이 실행 결과에서 계산하는 쪽을 먼저 검토한다 (가장 단순)
- 케이스 키는 계획 표와 같아야 한다: `scenario_case_settings`의 (spec_path, grep_filter). 실행 결과 → 계획 항목 매칭 규칙은 이미 있다: `service/PlanService.java`, `SiteCoverageService.suffixes`(리포트 경로가 testDir 기준 상대 경로라 접미사로 맞춤)
- 실행 결과 테이블: `execution_case_results` (`entity/ExecutionCaseResult.java`)
- API는 `/api/projects/{id}/defects` 아래에 두면 `ProjectAccessInterceptor`가 자동으로 멤버 검사를 한다 (조회는 GET이라 팀원도 됨)
- 필터: 상태(미해결 · 해결) · 화면 · 담당자(`assignee_user_id`, V18) · 스위트
- 마이그레이션이 필요하면 **V20부터**. V12 · V15는 김윤재 B트랙에 예약된 빈 번호다

## 6. 규칙

- 이슈 하나 = 브랜치 하나 = PR 하나, base는 `dev`. 커밋은 한국어 + `feat:`/`fix:`/`chore:`/`docs:` + 이슈 번호
- **PR을 쌓을 때 주의**: 지난번에 앞 PR 브랜치를 지우며 머지하자 뒤 PR이 "닫힘"으로 처리됐다. 쌓았다면 맨 위 PR 하나만 dev로 머지하고 나머지는 "함께 반영" 댓글로 닫는 방식이 안전하다
- PR 본문: `Closes #번호`, 무엇을 · 화면 스크린샷 · 알아 둘 것 · 확인한 테스트. 스크린샷은 `docs/screenshots/<브랜치>/`에 커밋하고 `?raw=true` 링크로 붙인다 (CLI는 PR에 이미지를 직접 못 올림)
- 테스트 먼저. 권한이 걸린 곳은 "막혀야 하는 경우"(403)를 테스트로 남긴다
- 화면 문구에 코드 용어 · 코드값을 쓰지 않는다
- 커밋 금지: `.env`, `storage/`, `playwright-projects/*`(단 `playwright-projects/playops-self/tests` 등 이미 추적 중인 파일은 고쳐도 됨), `AGENTS.md`/`CLAUDE.md`의 로컬 변경, `docs/aQm-산출물/`
- 비밀번호 · 토큰을 로그 · 커밋 · PR · 채팅에 남기지 않는다
