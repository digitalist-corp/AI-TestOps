## 1. 확정된 결정 (다시 묻지 말 것)

| 항목 | 결정 |
|---|---|
| 역할 | 전역 `ADMIN`/`USER` + 프로젝트별 `PM`/`MEMBER` (개편 ②에서 완료). 화면에는 "관리자 · PM · 팀원"만 |

## 2. 지금 코드 상태 (11/17 dev 기준)

**공지사항(#116)에 쓸 것**
- DB: `board_posts` 테이블이 V1에 이미 있다 (`type`, `title`, `content`, `pinned`, `visible`, `deleted`, `visible_from`, `visible_until`, `created_by`/`updated_by`는 VARCHAR, `created_at`/`updated_at`). **엔티티 · 코드는 없다.** 새 테이블을 만들지 말고 이것을 쓴다 (`type = 'NOTICE'`)
  - 같은 V1에 `board_post_comments` · `board_post_reactions`도 있지만 이번엔 쓰지 않는다
- 알림: `service/NotificationService.java` (`executionFinished`, `scheduleFailed`, `fixProposed` 패턴), `entity/Notification.java`, `controller/NotificationController.java`, 웹 `components/shell/NotificationBell.tsx` → 공지용 메서드 하나 추가해 모든 사용자에게 넣는다
- 관리자 전용 경로 막기: `config/ProjectAccessInterceptor.java`의 `adminOnly(method, path)`에 `/api/notices` 쓰기(POST · PUT · PATCH · DELETE)를 추가. GET은 누구나
- 좌측 메뉴: `apps/web/src/config/shellNav.ts` (관리자 전용은 `adminOnly`), 라우트: `apps/web/src/App.tsx`
- 역할별 첫 화면: `apps/web/src/pages/HomePage.tsx` → 최근 공지 3개

**프로젝트 기간 · 상태(#117)**
- 엔티티 `entity/Project.java`, 응답 `dto/ProjectResponse.java`, 요청 `dto/ProjectRequest.java`, 서비스 `service/ProjectService.java`
- 등록 · 수정 화면 `components/ProjectFormDialog.tsx`, 카드 `components/project/ProjectCard.tsx`, 첫 화면 `pages/HomePage.tsx`
- 진척률 계산은 이미 있다: 계획 표 "완료율 = 최신 성공 ÷ 사용 중 항목" (`lib/plan.ts`의 `planCounts`, 대시보드 `components/dashboard/PlanMetrics.tsx`). 새로 만들지 말고 재사용한다
- 상태 변경 권한: 관리자 · PM (권한 표상 "프로젝트 수정")

**수정자 · 수정일(#118)**
- JPA 감사(`@EnableJpaAuditing`, `AuditorAware`)는 **아직 없다**. 현재 사용자는 `AuthInterceptor`가 `request.setAttribute("currentUser", user)`로 넣는다 → `AuditorAware<Long>`이 `RequestContextHolder`에서 이 값을 읽게 한 곳만 만든다
- 요청이 아닌 곳(스케줄러 · 러너 콜백)에서 저장하면 사용자가 없다 → 그때는 `null`로 둔다 (실패시키지 말 것)
- `created_by` 타입이 테이블마다 다르다: `board_posts`는 VARCHAR(사용자 이름), `project_members`는 BIGINT(사용자 id). **새로 넣는 칸은 BIGINT(사용자 id)로 통일**하고, 기존 VARCHAR 칸은 건드리지 않는다

**계획 담당자 연결(#119)**
- `entity/ScenarioCaseSetting.java` (`assignee` VARCHAR(100), V11), `service/PlanService.java`, `dto/PlanDtos.java`, 웹 `components/project/PlanTab.tsx`
- 멤버 목록: `service/ProjectMemberService.java` (`list`, `roleOf`, `projectsOf`)
- 기존 `assignee` 글자는 지우지 않는다. 이관에서 못 찾으면 글자만 남겨 계획 표에 "(계정 없음) 홍길동"처럼 보여 주고, 다시 고르게 한다

**환경 컬럼 · 코드값 · 아이디(#120)**
- `server_type` 참조 위치: `entity/Project.java`, `dto/ProjectRequest.java`, `dto/ProjectResponse.java`, `dto/RunnerContainerResponse.java`, `service/ProjectService.java`, `config/DataLoader.java`, `chat/tools/AiRoViews.java`, 웹 `types/index.ts`, `components/ProjectFormDialog.tsx`, `components/project/recorder/RecorderStartPanel.tsx`, `pages/RunnerContainersPage.tsx`
- **주의: `V7__ai_readonly_views.sql`의 뷰 `ai_ro.projects`가 `p.server_type`을 쓴다.** 컬럼을 지우기 전에 같은 마이그레이션에서 이 뷰를 `server_type` 없이 `CREATE OR REPLACE VIEW`로 다시 만든다 (그렇지 않으면 DROP COLUMN이 실패한다). `AiRoViews.java`의 컬럼 설명도 같이 고친다
- 상태 이름표: 실행 상태는 이미 `apps/web/src/lib/utils.ts`의 `executionStatusLabel`로 모였다 (개편 ①). AI 작업 · 프로젝트 상태도 같은 파일에 모은다
- 프로젝트 아이디: 지금은 등록 요청의 `projectId`를 그대로 쓴다 (`ProjectService.create`, `validateProjectId`). 이 값은 **`playwright-projects/<id>` 폴더 이름과 러너 컨테이너 이름에도 쓰인다**. 새 아이디 규칙(예: `P0012`)은 폴더 · 컨테이너 이름으로 안전한 글자만 쓰고, 기존 프로젝트는 그대로 둔다
- ERD: `docs/aQm-산출물/그림_v3.0/ERD_v3.0_erdcloud.sql` (전체), `ERD_v3.0_erdcloud_핵심.sql`. ERDCloud에는 사람이 붙여 넣으므로 SQL 파일만 고친다 — **단, `docs/aQm-산출물/`은 아직 커밋되지 않은 폴더라 저장소에는 없다.** 이 항목은 PR 본문에 "ERD 반영할 테이블 · 컬럼 목록"으로 남기고, 파일 수정은 장준호가 한다

## 4. 환경 준비 · 검증

```bash
git checkout dev && git pull
npm run dev        # Docker Desktop 필요. Web :3000 · API :8080 · Postgres :5433

# API 테스트 (Mac에 JDK 없이 Docker로)
docker run --rm -v "$PWD/apps/api":/app -v api-gradle-cache:/home/gradle/.gradle -w /app \
  gradle:8.10.2-jdk21 ./gradlew test --no-daemon --console=plain

docker exec playops-web npx vitest run <파일>            # 웹 테스트 (특정 파일)
docker exec playops-web npx vitest run                   # 웹 전체
docker exec playops-web sh -c 'npx tsc --noEmit -p .'    # 타입 검사
```

- 마이그레이션을 추가한 뒤에는 `docker restart playops-api`로 다시 띄워 적용을 확인한다. 개발 서버가 떠 있는 동안 이 폴더에서 브랜치를 바꾸면 API가 깨질 수 있다 → 그때도 `docker restart playops-api`
- 웹 전체 테스트를 한 번에 돌리면 PlanTab 등 몇 개가 가끔 시간 초과로 실패한다. 그 파일만 다시 돌려 통과하면 PR 본문에 그렇게 적는다
- 브라우저 확인은 관리자 · PM · 팀원 계정으로. 테스트 계정은 회원가입으로 만들고, 비밀번호를 채팅 · PR에 적지 않는다

## 5. 규칙

- 이슈 하나 = 브랜치 하나 = PR 하나. 커밋은 한국어 + `feat:`/`fix:`/`chore:` + 이슈 번호
- PR 본문: `Closes #번호`, 무엇을 · 화면 스크린샷 · 알아 둘 것 · 확인한 테스트. 자동 병합 금지
- 테스트 먼저. 권한이 걸린 곳(공지 작성, 상태 변경)은 "막혀야 하는 경우"(403)를 테스트로 남긴다
- 화면 문구에 코드 용어 · 코드값(`PLANNED`, `NOTICE`, `DEV` 등)을 쓰지 않는다
- 커밋 금지: `.env`, `storage/`, `playwright-projects/*`, `AGENTS.md`/`CLAUDE.md`의 로컬 변경, `docs/aQm-산출물/` 등 아직 추적하지 않는 문서
- 비밀번호 · 토큰을 로그 · 커밋 · PR에 남기지 않는다
