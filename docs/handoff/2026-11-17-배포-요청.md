## 4. 단계별 절차

### 4-1. DB 백업

```bash
cd /home/playops/playops
mkdir -p ~/backup
# .env 의 POSTGRES_USER / POSTGRES_DB 를 쓴다 (기본값 playops / playops). 비밀번호는 컨테이너 안에서 필요 없다.
docker exec playops-postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > ~/backup/playops-$(date +%Y%m%d-%H%M).dump
ls -lh ~/backup/
```
- 백업 파일이 0바이트가 아니면 다음 단계로. 이 파일은 저장소 밖에 둔다 (커밋 금지).

### 4-2. 지워진 파일 되돌리기

```bash
cd /home/playops/playops
git status --short                       # 위 3개 파일 'D' 만 있는지 확인
git checkout -- playwright-projects/playops-self
git status --short                       # 아무것도 안 나오면 성공
```
- **`git status`에 위 3개 말고 다른 변경이 보이면 멈추고 장준호에게 알린다.** 서버에서 누가 직접 고친 파일일 수 있다. `git reset --hard`나 `git clean`은 쓰지 않는다 (`storage/` · `.env` 등 추적하지 않는 운영 데이터가 날아갈 수 있음).
- 앱에서 playops-self 프로젝트가 삭제된 상태라면, 파일을 되돌려도 앱 목록에는 다시 나타나지 않는다. 필요하면 배포 후 관리자가 다시 등록한다 (배포 작업과는 별개).

### 4-3. 배포 실행

- 4-2가 끝나면 장준호에게 알린다. 장준호(또는 장준호의 AI)가 V19까지 담은 dev → main PR을 만들어 머지하고, 그 머지로 배포가 자동 실행된다.
- 장준호가 바로 대응하기 어려우면, 먼저 실패했던 배포를 다시 돌려도 된다 (11/17 #115 버전까지만 반영, V14까지): GitHub → Actions → [실행 44090473130](https://github.com/digitalist-corp/AI-TestOps/actions/runs/44090473130) → **Re-run jobs**. 이후 장준호의 PR 머지로 V19까지 한 번 더 배포된다.

### 4-4. 배포 후 확인

```bash
cd /home/playops/playops
docker compose -f docker-compose.dev.yml ps                    # api · web · worker · postgres 모두 Up
docker logs --tail 200 playops-api 2>&1 | grep -iE "flyway|migrat|Started|ERROR" | tail -20
docker exec playops-postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "select version, success from flyway_schema_history order by installed_rank desc limit 10;"'
```
- 기대값: 마지막 버전이 **19**, 모두 `success = t`, API 로그에 `Started` 가 있고 `APPLICATION FAILED TO START` 가 없음
- 브라우저: 배포 주소에서 로그인 화면에 "회원가입" · "게스트로 시작"이 보이는지

**실패하면**
- 마이그레이션 오류로 API가 안 뜨면, 로그의 오류 줄을 그대로 장준호에게 보낸다. **DB를 직접 고치거나 `flyway_schema_history`를 손대지 않는다.**
- 되돌려야 하면 4-1 백업으로 복구한다 (복구는 장준호와 상의 후):
  ```bash
  docker exec -i playops-postgres sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists' < ~/backup/<백업파일>.dump
  ```

### 4-5. 앱에서 할 일 (관리자 계정)

배포 직후 권한 구조가 바뀌어 일반 계정에는 프로젝트가 보이지 않는다.
1. 관리자 계정으로 로그인
2. 프로젝트마다 설정 › **팀원** 탭에서 PM 지정, 팀원 추가 (팀원 추가는 PM도 가능)
3. 진행 중인 프로젝트는 설정에서 상태를 **"실행"** 으로 변경 (배포 후 모든 프로젝트가 "계획"으로 시작)

### 4-6. (선택) 환경변수

`.env`에 아래를 넣지 않아도 동작한다. 기본값은 게스트 아이디 `guest`, 비밀번호 없음(= "게스트로 시작" 버튼으로만 입장).
```
GUEST_USERNAME=guest
GUEST_PASSWORD=
```
값을 바꿨다면 `docker compose -f docker-compose.dev.yml up -d api`로 다시 띄운다. 비밀번호를 채팅 · 이슈 · 커밋에 적지 않는다.

## 5. 재발 방지 (장준호 쪽에서 PR 예정)

배포 사이트에서 playops-self 프로젝트를 다시 지우면 같은 이유로 배포가 또 멈춘다. 배포 스크립트가 "커밋되지 않은 변경 확인" 전에 `playwright-projects/` 아래만 git 기준으로 되돌리도록 고치는 PR을 장준호 쪽에서 올릴 예정이다. 그 전까지 같은 오류가 나면 4-2만 다시 하면 된다.

## 6. 하지 말 것

- `.env` · `storage/` · 백업 파일 커밋 금지
- `main` 브랜치에 직접 푸시 금지 (main은 dev에서 온 PR로만 바뀐다)
