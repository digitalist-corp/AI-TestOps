### [2] 오늘 오후 ~ 금요일 — LangGraph 학습 루프 (인수인계 11/18 문서 2절)

1. **E-04** 실패 수집 · 군집: 실패 메시지 · 로케이터 · 스택으로 서명을 만들어 같은 원인끼리 묶기

6. **E-09** 측정 · 판단: 최대 3회 반복, 예산 상한, 두 번 연속 진전 없으면 중단

지킬 것
- ai-service 는 compose 프로필 `ai` 에서만. 꺼져 있어도 기존 기능 · 시연은 그대로
- LLM 호출은 Spring 프록시 `/internal/ai-jobs/{id}/llm` 로만. 도구는 MCP(`/internal/ai-jobs/{id}/mcp`)로만 — 실행 번호를 받는 도구를 허용 목록에 넣을 때는 프로젝트 소속 확인을 붙인다(#158)
- 코드 반영은 사람 승인 뒤 `AiJobService.applyDiff` 로만. `ApprovalGateInventoryTest` 통과 유지
- 화면: 결함 · 실행 결과에 PM 이상만 보이는 "AI 루프로 고치기" 버튼 + "과거 수정 N건 참고" 표시. 프로필 `ai` 가 꺼져 있으면 숨기거나 안내

**금요일 저녁 완료 기준**
- 시연 데모 실패 1건으로 루프 한 바퀴: 분류 → 과거 수정 참고 → diff → 승인 대기 → 승인 → 재실행 통과
- 같은 실패를 한 번 더 넣으면 "과거 수정 1건 참고"가 보임 (= 테스트할수록 똑똑해짐 증명)
- 시연 데이터(진척률 80%, 미해결 결함 1건)와 demo-rehearsal 은 PR 마다 그대로 통과

## 3. 작업 방식

- 스킬: brainstorming → writing-plans → executing-plans(작업마다 TDD) → systematic-debugging(실패 시) → requesting-code-review → verification-before-completion. 보고에 언제 썼는지 적는다
- **토큰 절약**(준호 지시): 구현은 Sonnet. 리뷰 에이전트는 **main 배포 직전 1회만**. 테스트는 바뀐 범위만, 전체는 PR 직전 1회. 단계 끝날 때마다 `/compact`. 조사 · 탐색 하위 에이전트도 Sonnet, 워크플로는 꼭 필요할 때만
- 검증 명령(AGENTS.md): API `docker run --rm -v "$PWD/apps/api":/app -v api-gradle-cache:/home/gradle/.gradle -w /app gradle:8.10.2-jdk21 ./gradlew test --no-daemon --console=plain` — **로컬 `playops-api` 컨테이너가 떠 있으면 Gradle 잠금 충돌**이라 먼저 `docker stop playops-api`. 웹은 Mac 에 node_modules 가 없어 `docker exec playops-web npx vitest run` · `npx tsc --noEmit`. ai-service 는 `docker compose -f docker-compose.dev.yml --profile ai run --rm ai-service pytest -q` (코드를 바꾸면 이미지 재빌드)
- PR: dev 로. 쌓은 PR 은 dev 쪽 맨 아래 하나만 머지(위 PR 커밋을 그 브랜치에 앞당겨 넣음). 커밋은 한국어 + conventional type
- 사용자 미커밋 변경 `AGENTS.md` 는 건드리지 않는다
