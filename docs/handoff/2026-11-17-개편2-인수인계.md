## 1. 확정된 결정 (11/17, 다시 묻지 말 것)

| 항목 | 결정 |
|---|---|
| 회원가입 | 누구나 가입, **가입 즉시 팀원**(전역 `USER`). 승인 절차 없음 |
| 프로젝트 생성 · 삭제 | **관리자만**. 생성 화면에서 PM을 함께 고른다 |
| PM | **프로젝트마다** 지정 (`project_members.role = PM`). 지정 · 해제는 **관리자만** |
| 팀원 추가 · 제외 | 그 프로젝트의 **PM 또는 관리자**. PM은 다른 PM을 만들거나 뺄 수 없다 |
| 게스트 | 관리자 계정이 아니라 **별도 `USER` 계정**. 시연 프로젝트에 팀원으로 들어가 있다 |
| 반응형 | 모바일은 미룸. 새로 만드는 화면만 **1280px 이상 데스크톱**에서 깨지지 않게. 전체 점검은 배포 후 #108 |

전역 역할은 지금처럼 `ADMIN` · `USER` 둘만 둔다. PM · 팀원은 전역 역할이 아니라 **프로젝트 멤버 역할**이다. "관리자 > PM > 팀원" 판정은 `전역 ADMIN` → `project_members.role` 순으로 한다.

## 3. 지금 코드 상태 (11/17 dev 기준, 꼭 알아야 할 것)

**인증**
- 토큰 방식: `config/AuthInterceptor.java`가 `Authorization: Bearer` 토큰을 `AuthService.validateToken`으로 확인하고 `request.setAttribute("currentUser", user)`
- 인증 없이 통과하는 경로: `/api/auth/login`, `/api/health`, `/actuator`, `/internal/**` → signup을 여기에 추가
- 관리자 검사는 **`/api/admin/**` 경로 한 곳뿐**

**보안 구멍 (#105에서 반드시 막기)**
- `controller/UserController.java`가 `@RequestMapping({"/api/users", "/api/admin/users"})` — `/api/users`로 부르면 **관리자가 아니어도 사용자 생성 · 수정 · 삭제가 된다**
- `ProjectService.canAccess`는 `owner_user_id`로만 판단하고, owner가 비어 있으면 **누구나 접근**. 게다가 계획 · 실행 · 사이트맵 같은 프로젝트 하위 API 대부분은 `getProject(projectId)`를 user 없이 불러 검사 자체가 없다 (`getProjectForUser`를 쓰는 곳은 `ProjectService`, `RecorderService`뿐)
- 따라서 **#103(가입 열기)은 #105(권한 막기)와 함께 머지**해야 한다. 가입만 먼저 열리면 누구나 가입해서 사용자를 지울 수 있다

**시드 · 계정**
- `config/DataLoader.java`: `LOGIN_USERNAME` / `LOGIN_PASSWORD`(기본 admin/admin)로 `ADMIN` 계정 하나를 만든다 → 게스트 `USER` 계정을 여기 추가. 게스트 비밀번호는 코드에 하드코딩하지 말고 `.env`의 새 값(예: `GUEST_USERNAME` / `GUEST_PASSWORD`, `.env.example`에 자리만)으로
- 웹 로그인 화면 "게스트로 시작" 버튼: `apps/web/src/pages/LoginPage.tsx` (지금은 관리자 계정으로 로그인)

**웹**
- 로그인 정보 저장: `apps/web/src/api/client.ts` — `localStorage`에 `{ username, role }` 저장(:95), `api.login`(:145)
- 관리자 전용 메뉴: `apps/web/src/config/shellNav.ts`의 `adminOnly` (사용자 관리 `/users`) — 이 방식을 넓혀 쓴다
- 관리자 판정을 직접 하는 곳: `components/Layout.tsx`, `pages/AiSettingsPage.tsx`
- 사용자 관리 화면: `pages/UsersPage.tsx`
- 프로젝트 등록 버튼 · 목록: `pages/ProjectsPage.tsx`, 설정 화면: `pages/ProjectDetailPage.tsx`(설정 탭에 "프로젝트 정보" · 수정 · 삭제가 있음), 탭 정의: `config/projectWorkspace.ts`

**DB 마이그레이션**
- 현재 마지막 번호 V11. **V12는 B트랙(김윤재, 재실행 링크)에 예약** → 멤버 테이블(#104)은 **V13**으로 하고, PR 본문에 "V12는 B트랙 예약이라 V13 사용"이라고 적는다. 윤재가 V12를 아직 안 올렸어도 Flyway는 빈 번호를 건너뛰고 진행한다 (단, 나중에 V12가 들어오면 `outOfOrder` 설정이 필요할 수 있으니 PR에 적어 둘 것)
- 새 테이블에는 회의 요구대로 `created_by` · `created_at` · `updated_by` · `updated_at`을 넣는다

- 권한 검사(#105)는 컨트롤러마다 흩뿌리지 말고 한 곳에 둔다. 예: `/api/projects/{id}/**` 경로에서 프로젝트 id를 읽어 멤버 여부 · 역할을 확인하는 인터셉터 또는 `ProjectService.getProjectForUser`를 모든 하위 서비스가 쓰도록. 어느 쪽이든 "새 API를 만들 때 깜빡해도 막히는" 쪽을 고른다
- `GET /api/auth/me`(#105)로 전역 역할 + 프로젝트별 역할을 내려 주고, 웹(#106)은 그것만 보고 버튼을 나눈다. 웹에서 숨기는 것은 편의일 뿐, 막는 것은 서버다
- #107 팀원 대시보드: 내 프로젝트 리스트 + 성공 · 실패 · 미수행 집계 + 실패 재실행. 결함 리스트(#80 · #81)는 아직 없으니 자리만 두지 말고 빼 둔다. 프로젝트 시작일 · 종료일 · 상태(계획 · 실행 · 종료) 컬럼은 개편 ⑤ 범위이므로 만들지 않는다

## 5. 환경 준비 (macOS)

```bash
git clone https://github.com/digitalist-corp/AI-TestOps.git
cd AI-TestOps
git checkout dev && git pull
cp .env.example .env      # PLAYOPS_ENCRYPTION_KEY 는 `openssl rand -base64 32` 결과로 채운다
npm install
npm run dev               # Docker Desktop 필요. Web :3000 · API :8080 · Postgres :5433
```

## 7. 규칙

- 이슈 하나 = 브랜치 하나 = PR 하나. 커밋 메시지는 한국어 + `feat:`/`fix:`/`chore:` + 이슈 번호. 예: `feat: 회원가입 API와 게스트 계정 분리 (#103)`
- PR 본문: `Closes #10x`, 무엇을 · 화면 스크린샷 · 알아 둘 것 · 확인한 테스트. 자동 병합 금지
- 테스트 먼저: 권한 규칙은 특히 "막혀야 하는 경우"(403)를 테스트로 남긴다
- 화면 문구에 코드 용어(role, USER, MEMBER 등)를 쓰지 않는다 → "관리자 · PM · 팀원"
- 커밋 금지: `.env`, `storage/`, `playwright-projects/*`
- 비밀번호 · 토큰을 로그 · 커밋 · PR에 남기지 않는다
