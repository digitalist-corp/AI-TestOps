## 2. 양식을 지키는 방법 (가장 중요)

- **docx** (`anthropic-skills:docx` 스킬): 원본을 풀어서 `word/document.xml` 안의 텍스트와 표 행만 고치고 다시 압축한다. 새로 생성하지 않는다.
  - 표지, 머리글·바닥글, 개정 이력표, 목차, 장 번호, 표 스타일, 글꼴은 그대로 둔다.
  - 개정 이력표에 새 버전 행을 하나 추가한다.
  - 표 행이 모자라면 같은 표의 기존 행 XML을 복제해서 늘린다.
- **pptx** (`anthropic-skills:pptx` 스킬): 원본을 풀어 `ppt/slides/slideN.xml`을 고친다.
  - 화면이 늘어나면 `scripts/add_slide.py`로 비슷한 기존 슬라이드를 복제해서 쓴다.
  - 슬라이드 크기, 마스터, 색, 글꼴은 그대로 둔다.
- **ERD**: v3.0 html의 표기법·색·배치 규칙을 그대로 따른다.
  - SQL은 v3.0과 같은 ERDCloud 가져오기 형식으로 맞춘다.
  - `_핵심.sql`은 v3.0과 같은 기준으로 핵심 테이블만 고른다.
- **확인**: 만든 파일마다 PDF로 바꿔 이미지로 보고(스킬의 Verify 절차), **원본과 나란히 비교**한다. 표가 깨지거나 글이 넘치거나 빈 칸이 남았으면 고친다.
- 시작 전에 원본 6종을 먼저 읽는다(`pandoc -t markdown`, `slide_text.py`, `thumbnail.py`). 장 구성과 각 장의 분량을 파악한 뒤 같은 구성으로 채운다.

## 3. 내용의 근거 (이 순서로 믿는다)

1. **코드** — 실제 동작의 기준.
   - DB: `apps/api/src/main/resources/db/migration/V*.sql` (Flyway, V1~V22 이상)
   - API: `apps/api/src/main/java/com/playops/api/controller`
   - 화면: `apps/web/src/`
   - AI 서비스: `apps/ai-service`
2. **앱 사용설명서 v2.0** — `apps/web/public/guide/index.html`, 캡처는 `apps/web/public/guide/images/v2/`. 용어, 화면 이름, 역할, 흐름은 여기에 맞춘다.
3. **설계·계획 문서** — `docs/superpowers/specs/*.md`, `docs/superpowers/plans/*.md`, `docs/sitemap-api-contract.md`, `docs/dev-plan-v2.md`, `docs/architecture.md`, `docs/ai-integration-architecture.md`, `docs/langgraph-placement-decision.md`
4. **진행 기록** — `docs/handoff/*.md` (최근 날짜 우선), `git log --oneline`
5. **README의 프로젝트 차터** — 범위·현황·마일스톤을 2026-11-19 기준으로 이미 고쳐 두었다. 차터 docx와 마일스톤은 여기와 일치시킨다.

v3.0(11/17) 이후 새로 생긴 것들은 문서마다 반드시 반영한다.
- 역할별 홈: 관리자 / PM / 팀원. 계정 역할은 ADMIN·USER이고, PM·MEMBER는 프로젝트별 역할이다.
- 계획 표 CSV 내보내기, 진척률(사용 케이스 중 통과 비율), 진행 중 표시(남은 예상 시간)
- 실패 서명·군집과 원인 5종 분류(PRODUCT_DEFECT · SCRIPT_ERROR · ENVIRONMENT · FLAKY · UNCLASSIFIED), 평가셋 20건 중 18건 정확(90%)
- ai-service(Python LangGraph) + MCP로 Spring 도구 호출, 체크포인트는 PostgreSQL `langgraph` 스키마
- LangGraph 학습 루프: 분류 → 과거 승인 수정 회상 → 격리 수정·재검증 → 사람 승인(interrupt) → 반영 → 재실행
  - 정지 조건: 3회, 러너 15회, 정체 2회, 사람 거절, 환경·제품 결함
  - 학습 기억(V22), 실제 사이트를 가짜 화면으로 바꾼 수정은 `target_bypassed` 위험 표시 후 기억에서 제외
- 관리자 기본 비밀번호 강제 변경, 시연 데이터 시드·되돌리기, 배포 게이트(dev→main만 허용, 자체 회귀 통과)
- 아직 안 된 것(시연 뒤로 미룬 것)은 "계획"으로 적는다. 모바일, AI Task 알림, 저장소 코드 그래프 연결(#170), 사이트 탐색 2단계가 여기에 해당한다. **구현되지 않은 것을 구현됐다고 쓰지 않는다.**

## 4. 문서별 메모

- **PRD**: 기능 요구사항 ID 체계(FR-xx 등)는 v3.0 것을 유지한다.
  - 새 기능은 뒤 번호로 추가한다. 상태 칸(구현/계획)을 코드 기준으로 갱신한다.
  - 목표 수치는 README 차터 목표표의 측정값으로 채운다.
- **TRD**: 아키텍처 그림과 설명에 ai-service, MCP, LangGraph 체크포인트를 추가한다.
  - API 목록은 컨트롤러에서 뽑는다. DB 장은 ERD v4.0과 일치시킨다.
- **UI 설계서**: 화면 목록과 화면별 슬라이드는 앱 메뉴 순서(입력 → 계획 → 실행 → 대시보드 → 설정)와 역할별 홈을 따른다.
  - 캡처는 `guide/images/v2/`를 먼저 쓰고, 없는 화면만 로컬(`npm run dev`, http://localhost:3000)에서 새로 찍는다.
  - **AI 키·비밀번호·토큰이 보이는 캡처는 그 부분을 잘라내거나 가린다.**
- **마일스톤**: README 마일스톤표와 같은 일정으로 만든다.
  - 일정은 Sprint 1~4 완료, 11/21~24 동결·시연, 11/25~12/11 산출물 개정·최종발표(12/11)·회고다.
  - 표의 각 항목에 완료/진행/예정 상태를 표시한다.
- **ERD**: 마이그레이션 SQL에서 직접 테이블·컬럼·FK를 뽑는다. 기억이나 v3.0을 그대로 베끼지 않는다.
  - v3.0 이후 추가된 테이블과 컬럼을 표시한다. 학습 기억, 프로젝트 멤버, 공지, 계획 담당자 등이 해당된다.
  - `langgraph` 스키마는 라이브러리가 만드는 테이블이므로 ERD 본문에서 빼고 주석으로만 적는다.
- **차터**: README 차터 절(문제·목표·범위·팀·마일스톤·원칙)과 내용을 맞춘다. 기준 문서 버전 표기는 새 버전으로 바꾼다.

## 5. 지켜야 할 것

- `.env`, 비밀번호, API 키, 공유 계정 비밀번호를 문서에 쓰지 않는다. 계정은 "팀에 문의"로만 적는다.
- 앱 코드는 건드리지 않는다. 이번 작업은 문서만 한다.
- 커밋은 새 브랜치 `docs/deliverables-v4`에서 한다. 메시지는 한국어로 쓰고 `docs:`를 붙인다. 예: `docs: 산출물 v4.0 — PRD · TRD · UI 설계서 · 마일스톤 · ERD · 차터`
  - PR은 dev로 연다. main 직접 반영은 금지다.
  - 11/21~24 동결 기간에도 문서 PR은 dev로만 간다.
- 분량이 크면 문서 하나를 끝낼 때마다 커밋한다. 토큰이 끊겨도 다음 에이전트가 이어받을 수 있게 한다.
