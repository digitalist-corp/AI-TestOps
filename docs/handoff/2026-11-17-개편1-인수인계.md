## 1. 배경 (왜 하는가)

11/17 지도 회의에서 "화면에 코드 용어 · 쓰지 않는 칸이 너무 많고, 실행 · 삭제 동선이 위험하다"는 피드백을 받았다. 전체 개편 순서는 아래와 같고, **이 문서는 ①만 다룬다.**

1. **① 빠른 정리 (이 문서)** — 빼기 · 이름 바꾸기 · 확인 팝업. 화면 구조와 DB는 건드리지 않는다.
2. ② 역할 분리 — 관리자 · PM · 팀원, 프로젝트 멤버 테이블, 회원가입
3. ③ 역할별 화면 · 대시보드 (팀원 → PM → 관리자 순서, 반응형 포함)
4. ④ 공지사항 (관리자만 작성)
5. ⑤ 데이터 구조 정리 (수정자 · 수정일, 프로젝트 기간 · 상태, 환경 컬럼 삭제 등)

①에서 하지 않는 것: 권한 변경, DB 마이그레이션, 반응형. 게스트를 팀원 권한으로 바꾸는 일과 환경(server_type) 컬럼 삭제는 각각 ② · ⑤에서 한다.

## 2. 환경 준비 (macOS)

```bash
git clone https://github.com/digitalist-corp/AI-TestOps.git
cd AI-TestOps
git checkout dev && git pull
cp .env.example .env      # PLAYOPS_ENCRYPTION_KEY 는 `openssl rand -base64 32` 결과로 채운다
npm install
npm run dev               # Docker Desktop 필요. Web :3000 · API :8080 · Postgres :5433
```

- 로그인: 로그인 화면의 "기본 계정으로 시작" 버튼 (`.env`의 LOGIN_USERNAME / LOGIN_PASSWORD 시드 계정)
- Mac에는 JDK가 없어도 된다. API 테스트는 AGENTS.md의 Docker 명령을 쓴다.
- 프로젝트 규칙은 루트의 `AGENTS.md` · `CLAUDE.md`를 먼저 읽는다.

## 3. 검증 명령

```bash
docker exec playops-web npx vitest run <파일>      # 웹 단위 테스트 (특정 파일)
docker exec playops-web npx vitest run             # 웹 전체
docker exec playops-web sh -c 'npx tsc --noEmit -p .'   # 타입 검사
npm run build --workspace apps/web                 # 빌드
```

①은 웹만 바꾸므로 API 테스트는 필요 없다. 화면 확인은 http://localhost:3000 에서 직접 한다.

## 4. 작업 방식 · 규칙

- 이슈 하나 = 브랜치 하나 = PR 하나. 브랜치 이름 예: `feat/r1-1-wording`, `feat/r1-2-project-form`
- 커밋 메시지는 한국어, 앞에 `feat:` `fix:` `chore:`. 끝에 이슈 번호. 예: `feat: 로그인 버튼을 게스트로 시작으로 변경 (#93)`
- PR 본문에 `Closes #93`, 바꾼 화면 스크린샷 1~2장. base는 `dev`. 자동 병합 금지 (리뷰 후 사람이 병합)
- 테스트 먼저: 문구 · 동작이 바뀌는 곳은 기존 `*.test.tsx`의 기대값을 먼저 고쳐 실패를 확인하고 구현한다.
- 화면 문구에 spec · grep · env 같은 코드 용어를 쓰지 않는다.
- 커밋 금지: `.env`, `storage/`, `playwright-projects/*`

### #95 실행 확인 팝업 · 수정 · 삭제 위치 (11/19)
- 실행 버튼: `ProjectCard.tsx:280` 부근 "전체 테스트 실행" → 누르면 확인 팝업("<프로젝트 이름>을 실행할까요? 항목 N건"). 취소 시 요청을 보내지 않는다는 테스트 필수.
- 팝업은 삭제 확인(`ProjectsPage.tsx:153`)처럼 브라우저 기본 `confirm`으로 충분하다. 디자인이 필요하면 `components/ui`의 Dialog를 쓴다.
- 수정 · 삭제: `ProjectCard.tsx:303-306`의 아이콘 버튼을 빼고, 프로젝트 안의 정보 · 설정 화면(`config/projectWorkspace.ts`에서 정보 탭 확인)으로 옮긴다. 삭제 확인 문구(`ProjectsPage.tsx:154-156`)는 그대로 가져간다.

### #96 러너 진척도 · 리소스 현황 접기 (11/19)
- 카드의 "러너 · 실행 환경" 블록(`ProjectCard.tsx:245-272`)에서 환경변수 줄을 빼고, 실행 중이면 진척도(완료 N / 전체 M, 성공 · 실패)를 보여 준다. 실행 중이 아니면 최근 실행 결과 요약.
- 환경변수 입력이 필요하다는 경고(:272)와 환경변수 버튼(:297)은 실행에 필요하므로 유지.
- 리소스 현황: `components/ResourceStatusBar.tsx`, `components/Layout.tsx:158`. 접기 · 펼치기 버튼, 기본 접힘, 상태는 `localStorage`에 기억 (읽기 실패해도 깨지지 않게 try/catch).

### #97 화면 지도 핵심 화면 강조 (11/20)
- `components/project/structure/StructureGraph.tsx`에서 노드별 연결 수(들어오는 + 나가는 전환)를 계산하는 순수 함수를 `structure/` 아래에 두고 단위 테스트 (`layoutGraph.ts` · `layoutGraph.test.ts` 패턴 참고).
- `ScreenNode.tsx`: 연결 수가 많을수록 진한 배경, 최다 연결 노드는 강조 테두리. 노드 크기(256×128)와 배치는 바꾸지 않는다.
- 범례 컴포넌트는 따로 없다. `GraphToolbar.tsx`나 `CoverageSummaryCard.tsx` 근처에 "진할수록 연결이 많은 화면" 한 줄 설명을 둔다.
